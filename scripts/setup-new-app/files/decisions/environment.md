# Environment

- **One schema, generated outputs.** The root `.env` declares every setting with its type and default. The root `.env.local` holds this checkout's values. `bun run env:generate` (`env-manager gen --local`) writes the git-ignored values files and the tracked `env.ts` readers. Never edit a generated file by hand.
- **Readers are committed exactly as generated.** oxfmt and oxlint ignore them, so regenerating in a worktree or in CI never dirties the tree.
- **Local mode until values need to be shared.** `# env-manager local:true` in `.env` keeps env-manager offline and stops it from committing on its own. To move values into AWS Secrets Manager, run `env-manager set local false`, then `env-manager env set dev && env-manager up` to upload the current `.env.local` as `dev`. For `prod`, run `env-manager env set prod`, put the production values in `.env.local` with `APP_ENV=production`, and run `env-manager up`. From then on, `env-manager down` pulls the selected environment. Use the global `env-manager` for these: it loads the AWS credentials from its own checkout, which the pinned copy in `node_modules` cannot see.
- **Agents and CI never need AWS.** They run `env-manager gen --local`, which uses the schema defaults, so every default must be harmless and enough to start the app and run the tests.
- {{?worktree}}**Worktrees get their own ports.** `scripts/setup-worktree.ts` writes a git-ignored `.env.override` with a free two-port block. env-manager applies it on top of the root values for every target and never uploads it. Each app owns a 300-port range, so worktrees of different apps never collide: slot `(CLIENT_PORT / 10) % 75` of the root `.env` default starts at `10000 + slot * 300`. setup-new-app hands out main ports from 6000 in steps of 10, so the first 75 apps (6000-6740) get distinct ranges, all below the OS ephemeral ports. This app's range is {{WORKTREE_RANGE}}.
- **Secrets are optional in the schema and required in `config.ts`.** That keeps offline generation working. `{{SERVER_DIRECTORY}}/src/config.ts` lists the settings production needs in `REQUIRED_IN_PRODUCTION`, and the server refuses to start without them instead of failing on the first request that reads one.
- **`APP_ENV`** is `development` by default and `production` in `prod`.
