# stefan-utils

Shared Bun utilities and app scaffolding templates. Run `./scripts/setup-new-app/index.ts --help` for options (or `setup-new-app`, installed on PATH by running `bun link` in this repo).

```sh
setup-new-app --name my-app --type monorepo-swift
setup-new-app --name my-app --type monorepo-swift --overwrite-existing-repo
setup-new-app --name local-app --type client-server --repo none --localhost none
```

Types: `node`, `client-server`, `monorepo-swift`, `swift`, `empty`, and `chrome-extension`. Every web scaffold uses Svelte 5. `client-server` scaffolds a Bun workspace with a SvelteKit SPA in `apps/ui/`, a Bun API in `apps/server/`, and shared contracts in `packages/shared/`. `monorepo-swift` extends it with a SwiftUI app in `app-ios/`. Root `dev` runs UI and server; `ui:dev`, `server:dev`, and `start:ios` run each individually. Swift launcher arguments pass through, for example `bun run start:ios -t simulator`. `chrome-extension` is a Manifest V3 extension built with WXT, Svelte 5, and Tailwind; `bun run dev` opens Chrome with it loaded and reloads on save, and `bun run zip` packages it for the Chrome Web Store.

Client/server scaffolds use env-manager's single root `.env` schema with directory targets (`apps/ui`, `apps/server`, and `app-ios` for `monorepo-swift`) and explicit values/reader output paths. Setup runs `env-manager init --local` and `env-manager gen --local`, generating nested values files, TypeScript readers, and the native xcconfig and check script. Edit root `.env.local` and regenerate; generated child values are outputs. See each generated app's README and AGENTS files, plus `env-manager --help`, for details.

Overwrite mode deletes the entire local app folder, including ignored files and local values. It rebuilds current templates, skips GitHub repo creation and collaborator invitations, and force-pushes a fresh initial commit to the existing repo's default branch. Existing localias mappings are reused; missing mappings are created using `--port` or the next available port block. An explicit port must match an existing mapping. It requires an existing GitHub repo. `--repo none` cannot be combined with overwrite mode.

Templates live in `scripts/setup-new-app/files/`; generation lives in `scripts/setup-new-app/index.ts`. `client-server` and `monorepo-swift` share `files/client-server/`. Standalone and nested Swift share one initializer, source, Xcode project, launcher, and docs. Root config copying and localias setup are shared across all Bun scaffolds.

Every scaffold except `empty` includes GitHub Actions checks for its stack; `empty` has no stack to check, so it gets no CI. CI runs on pull requests and default-branch pushes, with every check as its own parallel job. Bun projects run `lint:ci`, `typecheck`, `test`, and `build` on every change with no change detection in front of them, pin the scaffolding runtime, cache downloads, and install from the lockfile. Swift projects run `swift test` on the Mac (`swift build` until a test target exists) and build the iOS simulator app with Xcode, caching package dependencies by toolchain. No job boots a simulator or a browser. The Swift jobs wait for a change-detection job, so they take a macOS runner only when native inputs changed and report success otherwise. CI never runs env-manager: the committed readers validate the tracked defaults. Generated `.github/CI.md` explains the checks and how to extend them; it lives outside `README.md` because GitHub shows `.github/README.md` in place of the root README.

Checks follow the `tests` skill in `~/code/ai-files/skills/tests/`, and `setup.md` there explains the choices. Each tool is the fastest for its job: oxlint and oxfmt, `bun check` (`svelte-check-native` for Svelte), `bun test`, and `swift test`. The pre-commit hook runs lint fixes on the staged files, the type check, and the whole test suite in parallel, with git's hook variables unset first, and no test runs at pre-push. Tests run in-process: TypeScript logic under `bun test`, and Swift logic in the `Core` library target under `swift test` on the Mac, which the Xcode app links as a static library. The app target has no test target.

Bun scaffolds (`node`, `client-server`, `monorepo-swift`, `chrome-extension`) also get the agent workflow tooling: a lefthook pre-commit hook installed by the root `postinstall`, and test preloads in `bunfig.toml`. Server scaffolds add `config.ts` with `REQUIRED_IN_PRODUCTION` and an `APP_ENV` setting. Every Bun scaffold's pre-commit hook first runs `agent-t3-worktree check --heal` when `~/bin/agent-t3-worktree` exists; worktree n uses the main ports plus `10000 + (n - 1) * 1000`, so apps 10 ports apart never collide. Repo-specific worktree steps go in a `worktree:setup` package script. The Swift launcher claims its simulator and, before a headless boot, waits for room through `agent-simulator`. env-manager readers are committed exactly as generated and excluded from oxfmt and oxlint.
